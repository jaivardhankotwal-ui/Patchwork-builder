---
name: Patchwork scope and guardrails
description: Product intent and boundaries for incident diagnosis
---
Patchwork is an autonomous production-crash diagnosis dashboard, targeting diagnoses and proposed code patches in under 60 seconds using GitHub file history and Gemini.

**Why:** The user's attached specification defines this workflow. Timing is a performance target, not a guarantee about external API latency.

**How to apply:** Keep attribution evidence-based and label synthetic incidents. The user explicitly expanded the original draft-only scope to include opt-in Autonomous Auto-Merge.

The user connected GitHub through Replit; Gemini uses Replit AI Integrations, while the dashboard also reports literal environment-variable presence separately.

**Why:** Managed connections avoid asking for credentials already available through integrations. A connected provider does not mean its traditional environment variable is set.

**How to apply:** Preserve both the environment indicators requested in the specification and truthful managed-connection indicators.

Slack notifications are requested after diagnosis and draft PR creation, with a manual send action. A signed Sentry receiver should trigger analysis and refresh the dashboard.

**Why:** The user expanded the workflow to include human-in-the-loop draft PRs, Slack incident alerts and live webhook ingestion.

**How to apply:** Draft PR links must not be called ready to merge without evidence; distinguish open, merged, closed and unconfirmed outcomes. If no PR exists yet, say so. Missing webhook credentials must be visible, not silently simulated.

Keep signing-secret entry in the workspace's secure Secrets tooling; settings may expose configuration status, not the secret.

**Why:** The user asked for in-app signing-secret entry before the shared dashboard had authentication. An unauthenticated setter would let any visitor replace the trusted webhook signing identity.

**How to apply:** Do not infer that merge-administrator grants also authorize editing infrastructure secrets; that would need a separate scope decision and secure storage design.

Treat generated regression tests and suggested run commands as untrusted proposals, not executed validation. Prefer adding a new test rather than replacing existing repository tests.

**Why:** Tests generated by the same model as a fix are not independent evidence of correctness, and overwriting an existing test could conceal a regression.

**How to apply:** Generated tests are proposed evidence, not independent proof that the model's fix is correct.
